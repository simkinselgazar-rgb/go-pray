## Contract changes (in `GoPray/Core/Contracts.swift`)

1. **`PrayerScheduleProviding.times(on:)` and `nextAthan(after:)` return optionals.** `nil` means "no valid schedule" (bad lat/lon, adhan-swift's failable `PrayerTimes` init returned nil). Reason: §G "bad schedule → no block" needs a way to say "no schedule". The gate and scheduler then never block. Lane A: return `nil`, never a made-up time.
2. **`Voice` is also `Codable`.** `Settings.voice` is saved to disk.
3. **The `Settings` struct lives in `Contracts.swift`** (the shape is the contract, §C.5). Lane A adds defaults, validation and `SettingsStore` as *extensions* in `Prayer/Settings.swift` / `Prayer/SettingsStore.swift`. Do not add or rename fields without a PM amendment. adhan-swift enums are stored as raw values so Core never imports Adhan:
   - `method: String` = `CalculationMethod.rawValue`
   - `madhab: Int` = `Madhab.rawValue` (1 shafi, 2 hanafi)
   - `highLatitudeRule: String?` = `HighLatitudeRule.rawValue`, `nil` = `HighLatitudeRule.recommended(for:)`
   - `SettingsError.blocked` is also in `Contracts.swift`.
4. **Name clash:** adhan-swift exports its own `Prayer` (with `.sunrise`). Inside our module `Prayer` is ours; write `Adhan.Prayer` for theirs.

## BlockGate API (`GoPray/Core/BlockGate.swift`)

5. Matches §C.3, plus:
   - `phase` is a **computed** get-only property (from the state + the clock), so clock jumps apply at once. Same external API as `private(set) var`.
   - `init` has **no `lockDuration:` param** any more: the lock comes from `Settings.lockMinutes` and is captured per block (#26). It has two extra defaulted params, `leavingTimeout: Duration = .seconds(4)` and `systemReduceMotion: () -> Bool`.
   - `authorizeSettingsChange() throws` (`SettingsError.blocked` during a block). **Lane A: `SettingsStore.mutate` calls this first for every change**, including mode, `lockMinutes` and pause/resume.
   - Read-only extras for UI: `currentBlock`, `hiddenAppName`, `shieldContext()`, `state`.
   - `BlockGate` is `@Observable` (lane A: read `gate.isBlocked` in views; use `TimelineView` for countdowns, since `phase` follows the clock).
   - `BlockGate` is the `ShieldDelegate`. It sets `shield.delegate = self` in `init`. Lane B never sets the delegate.
6. **Two private exits, both only in `BlockGate.swift`:** `endBlock()` (the confirmed end; one caller, `requestConfirm()`) and `failOpen(_:)` (window closed, next Athan replaces, crash loop, no schedule). `guard.sh` checks both.
7. **Lane B (shield):**
   - When the gate refuses `prayed`, it calls `shield.update(ctx)` with the true remaining time. That is the re-sync: on `update`, call `GoPrayBridge.show(ctx)` again.
   - Fail-open paths call `tearDown()`, which must work from any state, including during a `dismiss` fade.
   - Call `dismiss`'s completion on the main actor. If it is not called within 4 s, the gate calls `tearDown()` and goes idle anyway.
   - Gate order on a new block: write `state.json`, start the hider (coding mode), `audio.play`, then `shield.show(ctx)`.
8. **Lane C (audio):** `play` throwing is logged and the block still starts. `onFinished` → the gate sends `shield.update` with `athanRemainingMs = 0`. A relaunch never replays (`athanPlayed` is written `true` together with the block).
9. **Lane D (hider):** `start()` is called at block start *and* again on a relaunch that resumes a block in coding mode; `stop()` on every exit. Both must be safe to call more than once. `onReHide` after the block ended is ignored.

## state.json

10. **New optional field `lastDropped: {prayer, athanAt}`** (still schema v1; older files decode). It records a prayer given up by a fail-open rule while its window was still open (crash loop, corrupt or impossible file), so the wake rule does not block it again.
11. **"Done" rule:** a window whose Athan is at or before `max(lastConfirmed.athanAt, lastDropped.athanAt)` is never blocked again. This is how "clock back before a confirmed Athan → no second block" (§E.5) works with only one `lastConfirmed` record.
11b. **`block.lockSeconds`**: the lock length is copied from `Settings.lockMinutes` (clamped) when the block starts. Changing the setting later never shortens, ends or extends a running block, and that holds across a relaunch. A missing field decodes as 600. The gate never honours more than 1800 s (a tampered file cannot trap).
12. Dates are ISO 8601 with fractional seconds (plain ISO 8601 also decodes), so a resumed block keeps its exact start.
13. Launch-time validation: `blockStartedAt` more than 60 s before `athanAt`, or more than 60 s in the future → quarantine (`state.corrupt-<unix>.json`) + idle + the open window is dropped. While running, a clock that goes back only opens the button (clamp); it never quarantines.

## Scheduler

14. `scheduler.handle(_ reason:)` is the one entry for events: the gate re-evaluates, then the timer re-arms. Lane A's `SettingsStore` change hook calls `scheduler.handle(.settingsChanged)`. The timer is armed for the next Athan or the next local midnight, whichever is first. There is no re-arm on confirm, because confirming does not change the next Athan. **While paused, no Athan is armed**: the timer wakes at `pausedUntil` (kind `.pauseEnds` → `gate.reevaluate(.pauseEnded)`), or at midnight if that comes first (always for "until resumed"). Lane A calls `scheduler.handle(.settingsChanged)` after a pause or resume.

## Lock length + pause (PM amendment, Ahmed 2026-10-22)

26. **`Settings.lockMinutes: Int`**: 10–30, default 10. The rules live in `LockPolicy` (`Contracts.swift`): `minMinutes = 10`, `maxMinutes = 30`, `defaultMinutes = 10`, `clamp(_:)`, `seconds(forMinutes:)`. The value is captured into state.json at block start (#11b). `ReevalReason` gains `.pauseEnded`.
27. **`Settings.pausedUntil: Date?`**:
    - `nil` means active.
    - `.distantFuture` means "until I resume".
    - A past date also means active.
    - Choices come from `PauseOption` (`.oneDay`, `.threeDays`, `.oneWeek`, `.untilResumed`); use `.until(from: now)`. Calendar days, so a DST change does not shift it.
    - **Pause and resume are allowed only between prayers.** `authorizeSettingsChange()` throws during a block. A pause that slips past the store anyway neither ends nor shortens the running block (tested).
    - **To resume, set `pausedUntil = now`.** `nil` also works while the app is running.
    - Gate rule (stateless): a window whose Athan came before `pausedUntil` is never blocked. This covers a pause that ran out while the Mac was asleep or the app was down.
28. **First setup and resume never block the open window** (PM ruling a). When `setupComplete` goes false → true, or a pause ends (by expiry or resume), the gate marks the open window as dropped (`lastDropped`). Blocks start again at the next Athan.

## §E.3, read it this way (PM ruling b)

29. **Wake after the old prayer's window closed:**
    - The old prayer is missed and is never blocked.
    - If another prayer's window is open now, that prayer blocks at wake (`blockStartedAt` = wake), per §3.
    - If nothing is open (e.g. after sunrise, before Dhuhr) → idle.
    - Where §E.3 says "→ idle", it means "no block for the missed prayer", not "idle no matter what".

## TV control: the Athan also starts on a Roku (PM, lane tv-mac, 2026-10-24; TV Plan §3)

56. **The wire contract** (the Roku channel is built against exactly this): `POST http://<roku-ip>:8060/launch/<channelId>?prayer=<p>&voice=<v>`, empty body (`Content-Length: 0`). `p` is `fajr|dhuhr|asr|maghrib|isha`. `v` is `sunni.<stem>` or `shia.<stem>`, the same stem as `Resources/athan/{sunni,shia}/<stem>.mp3`, taken from `Settings.voice` (Fajr sends the chosen voice too; the channel plays its Fajr file). Path and query values are percent-encoded (everything but `A-Z a-z 0-9 - . _ ~`). `channelId` is `dev` for the sideloaded channel and becomes the published numeric id later; it is stored per TV (`^[A-Za-z0-9_-]{1,32}$`, else `dev`). No other ECP call is made (no keypress, no query except `device-info` for a name during a scan).
57. **Settings:** `tvs: [TVDevice]` (`id`, `name`, `kind` = `roku`, `host`, `channelId`, `enabled`). Absent key → `[]`; decoding is lossy per entry (an unknown `kind` or a broken entry is dropped, never the whole file; a non-array `tvs` → `[]`); missing `name`/`channelId`/`enabled` → `"Roku TV"`/`dev`/`true`. `host` is an **IPv4 literal** in 10/8, 172.16/12, 192.168/16 or 169.254/16 (`TVHost.isAllowed`: four plain decimals, no leading zeros, no spaces; loopback, public addresses and names are all refused). `Settings.sanitized()` DROPS any TV that fails it (refused at save; a hand-edited file cannot aim us at the internet and a bad entry cannot lock all settings), dedupes by id and by host, caps at 8. `RokuTV.launchURL` checks again at send (skipped, one log line). The test seam is `RokuTV(hostCheck:)`; production never allows 127.0.0.1. Windows ignores the key until its own parity lane.
58. **The hook:** `BlockGate.present(freshAthan:)` calls `tv.athanStarted(prayer:voice:tvs:)` right after `audio.play` (also when the Mac's own play threw: the TV is the household's Athan). It sits inside `if freshAthan, !silenced`, so it fires only when a block STARTS: the live Athan and wake into an open window. Never on a relaunch mid-block (`freshAthan: false`), never on Silence, never while paused (no block starts, so `present` is never reached; tested). Fire and forget: `TVController.athanStarted` returns at once and sends on detached background tasks, 3 s request and resource timeout, ephemeral session (no cookies, no cache), redirects refused. Every failure is one `os_log` line (`tv` category) and nothing else. `BlockGate.init` gains `tv: TVSending = NoTV()`; only `AppEnvironment.live()` passes the real `TVController()` / `RokuDiscovery()`.
59. **Discovery:** SSDP `M-SEARCH` for `ST: roku:ecp` to the multicast group, 3 s, over a BSD UDP socket. The TV's address is the datagram's sender (never the `LOCATION` header), and must pass `TVHost`. The name comes from `GET :8060/query/device-info` (`user-device-name`, else `friendly-device-name`, else `model-name`).
60. **Settings UI:** a "TVs" section after Athan. Find TVs (Scan), Add by address, and per TV: name (saved on Return or leaving the field), on/off, Test, Remove. **Test** launches the NEXT prayer with the current voice on that one TV (even if switched off) and shows one line, "Sent." or "Couldn't reach that TV." The whole form is disabled during a block, and the model refuses scan/test/changes while blocked. One help line: "Your TV needs the Go Pray Roku app."
61. **macOS Local Network permission (found live, 2026-10-24):** a debug build run headless (xcodebuild test) is refused with `NSURLErrorDomain -1009` and the system log says "Local network prohibited". `Info.plist` gains `NSLocalNetworkUsageDescription`; the first LAN contact by the real app shows the system prompt. **Open question for the PM:** a TV added by typing its address makes no network call until the first Athan or Test, so the prompt could first appear at an Athan. Suggest: one `device-info` ping when a TV is added by address (not built).
62. **guard.sh:** rule 4 allows `URLSession` in a third file, `TV/TVController.swift`; new rule 4c: raw socket calls (`socket/sendto/recvfrom/bind/connect`) and Network.framework only in that file, and that file holds NO hostname, URL or IP literal inside a string (comments are stripped before matching; the only allowed IP literal is the SSDP group). `:8060`, `/launch` and `"http"` alone are fine. Negative controls (planted `http://…`, planted `livingroom.local`, planted `192.168.1.160`, socket/NWConnection elsewhere, URLSession in `TVDevice.swift`) and positive ones are in `guard-selftest.sh`. `allowingReadAccessTo` is still exactly 1.

64. **Amendment (PM, 2026-10-24): the channel id is looked up, never hardcoded.** The store channel is "Go Pray: Athan & Adhan", so the id will not stay `dev`. When a TV is added (scan or by address) and on every Test press, `GET :8060/query/apps` (`RokuTV.findChannel`) and take the app whose name starts with "Go Pray"; a published numeric id beats `dev` when both are installed. The result is stored in `TVDevice.channelId`; **the Athan path makes no extra call** and uses the stored id. The XML is untrusted LAN input: `XMLParser` (no external entities), 512 KB cap, and only ids matching `^(dev|[0-9]{1,10})\z` are accepted (`TVDevice.isValidChannelId`, which also guards the URL path and `sanitized()`). No Go Pray app found → `TVDevice.installed = false` (new key, absent → `true`): Settings shows "Go Pray isn't installed on this TV yet", `athanStarted` skips the TV with one log line, and the Test button re-checks first (so installing later just works). A TV that can't be reached at add time is still added and keeps `dev` / installed. `TVSending` gains `resolve(_:) -> .found(id) | .notInstalled | .unreachable`.
65. **Local Network prompt (PM ruling, 2026-10-24).** The add-time `GET /query/apps` (#64) is the first network call, so the macOS prompt appears in Settings, not at an Athan; no separate ping. From the Go Pray debug app run headless, the same `sendto` to the multicast group fails with errno 65 (EHOSTUNREACH), the same Local Network refusal; `RokuDiscovery.scan()` now returns `TVScan{found, denied}` and the Scan row shows the same line. 66. **Amendment (PM, 2026-10-24): several computers on one Wi-Fi.** The TV de-dupes per prayer per day, but a laptop opened long after the Athan must not start the TV late. In `BlockGate.present(freshAthan: true)` the TV is called only if `now - block.athanAt <= 180 s` (`BlockGate.tvLateWakeLimit`; `athanAt` is the real prayer time from the schedule, not the block start). A live Athan always passes (the scheduler fires at the Athan time). 67. **Amendment (PM, 2026-10-24): do not restart a channel that is already playing.** A repeat `/launch` restarts the Roku channel (it resumes at the right spot, with a short audio gap). So an Athan launch (not Test) first does `GET :8060/query/active-app` (`RokuTV.activeAppID`: the same bounded read and XMLParser rules as `query/apps`). If the active app id equals the stored `channelId`, the launch is skipped (`tv: already playing`). Any error, timeout, bad status or unreadable reply on that check → the launch is sent anyway (the TV de-dupes as the backstop). The Test button never checks and always launches.
