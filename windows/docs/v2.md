# Go Pray for Windows v2: what was built (PLAN-v2 §4 brief)

Built 2026-10-24 on `windows`. All three features are in: the editable blocked-apps list, emergency exits, and the update check. The shield page's button is not, because `bridge.js`, `shield.html` and `shield.css` come from the Mac lane.

## 1. Blocked apps (PLAN-v2 §1)

**Settings JSON.**
- `settings.json` gains `customApps`, `disabledDefaultApps`, `emergencyExitsEnabled` and `checkForUpdates`.
- The keys are sorted and always written.
- In a 0.1.x file the four keys are absent, and they decode as `[]`, `[]`, `true` and `true`.

**Defaults and the effective list.**
- The defaults stay in `CodingApps.Names`. `CodingApps.Defaults` is the same list, normalised, in table order.
- The effective list is `BlockedApps.Effective` in Core. It is computed as (defaults − disabled) ∪ custom[windows], minus `BlockedApps.NeverBlock`.

**Captured at block start.**
- `state.block.hiddenApps` is written at block start. The hider gets that list, never the settings.
- A 0.1.x block that is resumed fills the list in once and writes it back.
- On read, never-blockable ids are dropped and the list is capped at 200. Ids are kept as written, so a Mac file's bundle ids round-trip; the hider normalises them itself.

**AppHider.**
- `AppHider.Start(ids)` hides exactly that set.
- It refuses NeverBlock processes even if they are passed in. This is the last line of defence.

**Settings → Blocked apps.**
- Each default has a switch. The person's own apps have Remove.
- "Add an app…" offers the running apps with a window, plus Browse… for an `.exe`.
- A Windows part of the system is refused with "Go Pray can't rest that one. It's part of Windows.", and a duplicate with "Already on the list."
- Picking a default that was turned off turns it back on.

## 2. Emergency exits (PLAN-v2 §2 + §9; PM 2026-10-24)

**The ledger.**
- `EmergencyLedger` keeps two stores: `%LOCALAPPDATA%\GoPray\emergency.json` and the mirror `%APPDATA%\GoPray\emergency.json`. Both have the same bytes as the Mac's file.
- The year rule counts uses in this local calendar year, plus every use dated after now.
- Remaining = 5 − the larger of the two counts, never the sum.
- An unreadable store, a wrong schema or more than 1000 uses means 0 left.
- `RecordUse` writes the primary first. If that write fails, the exit is refused.

**The gate.**
- `RequestEmergencyExit()` is the second and last caller of `EndBlock`. It is allowed while locked or at canConfirm.
- It also needs the switch captured at block start (`state.block.emergencyExitsEnabled`) and at least one exit left.
- The ledger write comes first. The prayer is recorded in `lastDropped`, never `lastConfirmed`.
- `Dismiss(kind: Emergency)` is a plain close with no accept line.

**The shield.**
- `ShieldContext.EmergencyExitsLeft` is 0 when the switch is off, and 0 hides the button.
- The bridge accepts the message `emergency`, and the payload gains `emergencyExitsLeft` (0–5).

**The native fallback.**
- A quiet footer reads "Emergency exit · N of 5 left this year".
- Press and hold for 3 s. The hold is on a Border, so no key can press it.
- Then a confirm card appears with "Not now" as the default, and "Use it" sends one request.

**Menu and Settings.**
- The menu shows "Emergency exits: N of 5 left this year", "…none left until 1 January" or "…off".
- Settings → Block has the "Allow emergency exits" switch with its help line and the same count.

**Debug only.** The Debug menu has "Emergency exits (debug) used: 0–5". The harness has `--exits-used`, `--exits-off`, `--emergency-at` and `--emergency-hold-at`.

**Uninstall.** Answering "Yes" to removing data also deletes `%APPDATA%\GoPray`. A full uninstall resets the exits; that is an admin act (§2.4).

## 3. Update check (PLAN-v2 §8)

**Where and when.**
- `GoPray.App/Update/UpdateChecker.cs` makes one anonymous GET to the GitHub releases API (User-Agent `GoPray`).
- It looks only at `win-v` tags, takes the highest, and offers it only if it is strictly newer.
- It checks 30 s after launch, then daily, and on wake. Settings → General → "Check for updates automatically" (`checkForUpdates`) controls the automatic checks.
- The tray's "Check for updates…" always works.
- It never runs during a block: no request, no download, no installer.

**Download and verify.**
- The asset URL must be exactly our repo's download path, and the file at most 300 MB.
- Redirects are followed by hand, https only, to GitHub's hosts only.
- Before running, three checks: the SHA-256 matches the `.sha256` asset, `WinVerifyTrust` accepts the file, and the signer CN is "Ahmed Elgazar".
- If any check fails, the file is deleted and the menu says "Couldn't verify the download. Get it from GitHub."
- If all pass, the installer runs and the app quits.

**Memory.** `update.json` holds `schemaVersion`, `lastCheckedAt` and `latest`. Downloads go to `updates\`, which is cleared at launch.

## guard.ps1

- **Rule 1:** the `EndBlock` callers are `RequestConfirm` and `RequestEmergencyExit`, so `EndBlock(` has 3 hits.
- **Rule 4:**
  - Network APIs are allowed only in the Geocoder and the UpdateChecker.
  - GitHub URLs, `WinVerifyTrust`, `CreateFromSignedFile` and `GoPray-Setup` appear only in the UpdateChecker.
  - The repo is pinned once.
  - `Process.Start(` is allowed only in the UpdateChecker, LogonTask and Credits.
- **Rule 10 and the -Release scan:** the new debug names are covered.
- **Rule 14 (new):** `emergency.json` is named only in the ledger. `RecordUse(` appears only in the ledger, plus exactly one call in `RequestEmergencyExit`.
- **Fixed:** the comment stripper treated `//` inside a string (`"https://…"`) as a comment. That had hidden every URL from the guard.
- **guard-selftest:** 55 controls (11 new negative controls).

## Differences from the plan text (for the PM)

1. **Future-dated uses (§9.1 vs §2.3):** a use dated after now always counts. The §2.3 rules "> 24 h in the future → 0 left" and "used.count > 5 → 0" are replaced by the year rule, plus the Mac's "> 1000 uses → 0".
2. **Download hosts:** besides `github.com` and `objects.githubusercontent.com`, the hosts include `release-assets.githubusercontent.com`. That is where GitHub serves release assets today.
3. **The web shield's emergency end:** until `bridge.js` has `dismiss("emergency")`, `Dismiss(Emergency)` closes web slots directly instead of asking the page to fade. Today's page would show "May Allah accept it."
4. **Mode** is still read from settings and not captured. That is unchanged from v1, because settings cannot change during a block.
