# Go Pray for Windows — build plan

Source of truth for the Windows port. Written 2026-10-22 by the Mac PM's architecture review; the Mac app in this repo (`GoPray/`) is the reference implementation. Decisions already made by Ahmed are marked in §9.


Fable, 2026-10-22, for the **general windows worker** (a Claude session on Ahmed's Windows PC that only sees what we send it plus the public repo https://github.com/simkinselgazar-rgb/go-pray). Read for this plan: the Mac app's locked decisions and architecture plan (summarized here), and the Mac code in this repo (read-only reference) (`README.md`, `CONTRACT-NOTES.md` #1–48, `GoPray/Core/Contracts.swift`, `GoPray/Core/BlockGate.swift`, `GoPray/Core/BlockState.swift`, `scripts/guard.sh`, `GoPray/Resources/scenes/shield.html` + `bridge.js` + `MANIFEST.sha256`, `audio/LICENSES.md`). Windows API facts were checked against Microsoft Learn today; anything not checked is marked **UNKNOWN** and gets a spike question in §7 Phase 0.

**Bottom line.** Port the law, reuse the art. The Mac app already split itself into "Swift decides, the page asks" (Final plan §B), so the Windows app is: a 1:1 C# port of `Core/` (gate, state, scheduler, tests), the same eight approved scene files + `shield.html` + `bridge.js` byte-identical inside WebView2, the same 29 audio files, and a new Windows shell (shield windows, keyboard guard, hider, tray, Task Scheduler autostart). Windows gives us a **public** media-pause API (better than the Mac) and takes away the easy full-screen cover (no `.screenSaver` level; the shell's own windows are topmost peers), so the shield needs two extra mechanisms the Mac does not: a foreground re-assert and a low-level keyboard hook (decision 2 for Ahmed).

### 1. Avatar + first principles

- **Avatar:** the same Muslim builder/coder, on Windows: Ahmed's PC first, then anyone who downloads the installer. Wants the same thing: stopped at every Athan, let back after a real break, nothing to remember. Fears, same: a lockout mid call, a bug that traps him, an app so annoying he removes it.
- **What is different on Windows.**
  1. **The reflex kill is Task Manager.** On the Mac it was Cmd-Q / Force Quit; on Windows it is Ctrl+Shift+Esc → End task. It is four deliberate steps, but every Windows user knows them.
  2. **Covering the screen is harder.** There is no window level above the shell. The taskbar, Start, Alt-Tab switcher and notification centre are topmost windows like ours. The shell *does* hide the taskbar under a foreground window that exactly covers a monitor, and Windows hooks *can* swallow Alt+Tab, Ctrl+Esc and the Win key — Ctrl+Alt+Del and Win+L are OS-reserved and stay (good: locking the PC is walking away).
  3. **Pausing media is a public API** (`Windows.Media.Control`), and it can pause every session, not only the current one.
  4. **Trust looks different.** A new signed exe still shows a SmartScreen "Windows protected your PC" until the certificate/file earns reputation; a user who fears malware is a real avatar fear here. Code signing via Azure Artifact Signing + a plain Inno installer + the GitHub README are the answer; winget later.
  5. **No Background Items / BTM.** None of the Mac's single-instance waiter, hand-over, successor or agent-repair machinery (CONTRACT-NOTES #36, #42, #44) is needed. A Task Scheduler logon task runs once per logon; a named mutex handles a second hand-opened copy.
- **First principles, unchanged:** one timer, one cover, one file that remembers "we are blocked". Code only; no AI, no network except the typed-city lookup. Two rules in this order: **never trap him** (fail open), then **no escape by reflex**. Ahmed is the admin and can always get out (Ctrl+Alt+Del, sign out, another account).
- **Delete on Windows:** everything in the Mac that exists because of `RunAtLoad` + `SMAppService` (#36, #42, #44, #45), MediaRemote/dlopen (we have a public API), `SceneStill` WKWebView snapshots (Windows UI uses the five PNG stills exported once from the scenes instead; smaller, no second web view).

### 2. Stack

**Pick: C# on .NET 10 (LTS), WPF for windows, WebView2 for the scenes, WinForms `NotifyIcon` for the tray, `Windows.Media.Control` via the built-in WinRT projection, NAudio for sound. One solution, one language, Microsoft tooling end to end, signs cleanly with `signtool`.**

### 4. Shared vs ported, and repo layout

**Shared, byte-identical, single source of truth in the existing tree:**
- `GoPray/Resources/scenes/`: the eight approved files (`watercolor.js`, `ui.js`, `fajr.js`, `dhuhr.js`, `asr.js`, `maghrib.js`, `isha.js`, `styles.css`), `fonts/` (2 WOFF + 2 OFL), and the app-only `shield.html`, `bridge.js`, `shield.css`, all pinned by `MANIFEST.sha256`. The Windows build **copies from this folder at build time** (`windows/scripts/sync-assets.ps1`) and `check-manifest.ps1` fails the build if any byte differs. The Windows tree never holds a second copy in git.
- `GoPray/Resources/athan/` (16 Sunni + 12 Shia + 1 Fajr) and `audio/LICENSES.md`, `GoPray/UI/CreditsViewData.swift` as the credits text source (the worker ports the strings to `Credits.cs`; the PM diffs them).
- Bridge message names, `state.json` and `settings.json` schemas, `LockPolicy` constants, `PauseOption`, the coding-apps *concept*, all copy (README rules section, setup/settings strings).

**Ported (new code, same design):** `Core/*` (Contracts, Clock, BlockState, StateStore, BlockGate, Scheduler) → `GoPray.Core`; `Prayer/*` → `GoPray.Core/Prayer` (schedule via the Adhan port, Settings, SettingsStore) and `GoPray.App/Prayer/Geocoder.cs`; `Shield/*`, `Blocker/*`, `Audio/*`, `Launch/*`, `UI/*`, `Debug/*` → `GoPray.App`. Tests: `BlockGateTests` (34 cases), `LockAndPauseTests`, `SchedulerTests`, `DebugBlockTests`, `BridgeMessageTests`, `AppHiderTests` (with a fake window enumerator), `SettingsStoreTests`, `PrayerScheduleTests` (+ the Mac parity fixture) → xUnit, same test names so the PM can diff coverage.

**Repo layout: one repo, `windows/` folder at the root of `go-pray` (recommend) — not a second repo.** Reasons: the scenes, audio and licences are shared and manifest-checked from one place (a second repo would mean a copy that drifts); one Releases page where the DMG and the Windows installer sit side by side; one README with two download buttons; one issue tracker. The Xcode project ignores `windows/`; the .NET solution never reaches outside `windows/` except through `sync-assets.ps1`, which reads `../GoPray/Resources/`. Branching: the worker pushes **`windows`** (a branch on `origin`; never `main`). The PM merges it into the local private `main` and publishes by squashing onto `public` as today. Pre-ship review of the Windows code happens on that branch before the merge.

### 5. Signing + distribution

**Code signing: Azure, via one of two services. Which one Ahmed has is UNKNOWN; "Trusted Signing" was renamed "Artifact Signing" in 2026 (docs updated 2026-05), so his portal may show either name.**

| | **Artifact Signing** (formerly Trusted Signing) | **Key Vault certificate** |
|---|---|---|
| What exists in Azure | An *Artifact Signing account* (Basic or Premium SKU) in a supported region (East US, West US 2, West Europe, …), a completed *Identity validation* (individual: **US or Canada only**, billing account type *Individual*, government ID through AU10TIX; or organization: legal entity + business identifier), a *Certificate profile* of type **Public Trust** | A Key Vault holding an OV/EV code-signing certificate (imported `.pfx` or CA-issued into the vault; EV needs HSM-backed Premium vault) |

### 6. Security / no-escape threat model (Windows)

**Must never (and the guard or test that proves it):**
- Kill or close any process or window: no `Process.Kill`, `TerminateProcess`, `taskkill`, `WM_CLOSE`/`WM_QUIT` to foreign windows, `SW_HIDE` (`guard.ps1`). Minimize only, listed exes only (`AppHiderTests`).
- Log, store or transmit keystrokes. `KeyboardGuard.cs` is the only file with `SetWindowsHookEx`; its callback is a pure function `Decide(vk, flags, winDown, comboSeen) → Swallow|Pass` (unit-tested), and that file may not reference `File`, `Console`, `Debug.Write`, `ILogger`, `StringBuilder` or any collection (`guard.ps1` bans them in that file). No `SendInput`, `keybd_event`, `mouse_event`, `GetAsyncKeyState`, `GetKeyboardState` anywhere. Hook installed only while a whole-screen block is up; `UnhookWindowsHookEx` in `EndBlock`, `FailOpen`, `tearDown` and the process-exit handler.
- Change system policy: zero hits for `DisableLockWorkstation`, `DisableTaskMgr`, `DisableChangePassword`, `NoLogoff`, `HideFastUserSwitching`, `Policies\System`. We never block Ctrl+Alt+Del, Win+L, sign-out, shutdown, sleep, user switch.
- Open the network except `Prayer/Geocoder.cs` (`HttpClient`, `WebRequest`, `Socket` pinned there); WebView2 `connect-src 'none'` CSP + `NavigationStarting` cancel for any URL not under the virtual host; `NewWindowRequested` handled; `FrameNavigationStarting` cancelled.
- Run elevated (manifest `asInvoker`), as a service, or in another session (the task is per user, `RunOnlyIfLoggedOn`; mutex is `Local\`).
- Read or write outside `%LOCALAPPDATA%\GoPray\` and its own install folder.
- Ship a Release build with any debug entry (`guard.ps1 -Release` string scan; `#if DEBUG` on every entry).

### 9. Two decisions for Ahmed

1. **Task Manager "End task" mid-block.** Option A (recommend): Task Scheduler restart (back in ≤ 60 s with the original timer) **if** Phase 0 shows the restart fires after End task; if it does not, End task becomes an accepted bypass and the block resumes at the next launch or logon, same as "launch at login off" on the Mac. Option B: a second watchdog process that relaunches Go Pray within a second. **Recommend A.** End task via Ctrl+Alt+Del is four deliberate steps, not a reflex; a pair of processes resurrecting each other is the shape of malware, doubles the signing and uninstall surface, and is the kind of thing SmartScreen and antivirus flag. The Mac already accepted `ssh` + `launchctl bootout` for the same reason.
2. **The low-level keyboard hook.** Option A (recommend): install `WH_KEYBOARD_LL` only while a whole-screen block is up, swallowing Win tap, Win+combos (except L), Alt+Tab, Alt+Esc, Ctrl+Esc, Ctrl+Shift+Esc; pure callback, nothing stored, pinned to one file by the guard, dies with the process, and the OS drops it if we hang. Option B: no hook; rely on the topmost windows + foreground re-assert only, so Start and Alt-Tab stay reachable for a moment and a reflex escape is half-open. **Recommend A.** It is the only way to make the reflex dead on Windows, and the guard rules in §6 make it provably not a keylogger. If Ahmed prefers B, the plan still works; §6 row 1 moves to "accepted bypass".
